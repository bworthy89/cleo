## Change #1 — NFE 12 → 20, CFG 2.5 → 2.0

**Date:** 2026-04-20

**Why:**
- F5-TTS paper only benchmarks NFE at 16 and 32. NFE=12 is below the tested
  floor; flow-matching models degrade non-linearly below tested NFE. This is
  the likeliest single cause of between-run robotic-ness.
- CFG=2.5 is above `utils_infer.py` default (2.0). Higher CFG = more stable
  output at the cost of expressivity. Paper uses CFG=2.

**Change:** `server/.env`
- `F5TTS_NFE_STEP=12` → `F5TTS_NFE_STEP=20`
- `F5TTS_CFG_STRENGTH=2.5` → `F5TTS_CFG_STRENGTH=2.0`

**Expected impact:** Large. Reduced run-to-run variance (NFE) + more natural
prosody (CFG). Expected per-call cost: ~7s → ~11s on 6700XT.

**Outcome:** _pending listen test_

## Change #3 — Reference transcript fix (ONAY → Oh-nay, em-dash → comma)

**Date:** 2026-04-20

**Why:** Audit of `/home/kari/f5tts-server/refs/onay-cartesia.txt` revealed
two mismatches between the reference transcript and what `preprocessForTTS`
emits as gen_text:

1. Transcript contained literal `ONAY`, but every gen_text has `ONAY → Oh-nay`
   applied before send. Reference alignment learns one token pattern, inference
   asks for a different one — permanent drift on every bake.
2. Transcript contained em-dash `—` (U+2014), but `preprocessForTTS` converts
   em-dashes to commas in gen_text. Same mismatch category.

Since the reference audio was generated by Cartesia using its pronunciation
dict (`CARTESIA_PRONUNCIATION_DICT_ID`), the audio almost certainly says
"Oh-nay" rather than letter-spelled "O-N-A-Y," so rewriting the transcript
to match is the correct direction.

**Change (on F5 server):** `~/f5tts-server/refs/onay-cartesia.txt`

Before:

```text
Welcome back to the late show — I'm your host ONAY. I've been digging through the archives for some hidden gems tonight. Stay close. This next track has a story.
```

After:

```text
Welcome back to the late show, I'm your host Oh-nay. I've been digging through the archives for some hidden gems tonight. Stay close. This next track has a story.
```

Backup saved: `onay-cartesia.txt.bak-20260420`.

**Expected impact:** Medium-large. Every single generation benefits; likely
contributor to "sometimes natural / sometimes robotic" since alignment drift
manifests differently per gen_text.

**Outcome:** _pending listen test_

## Confirmed via server inspection (no change needed)

- **Text chunking is automatic.** `F5TTS.api.F5TTS.infer` → `infer_process` →
  `chunk_text(gen_text, max_chars=adaptive)`. Formula:
  `max_chars = int(len(ref_text_bytes) / (audio_len_s) * (22 - audio_len_s) * speed)`.
  For current 8.97s ref: ~140 chars/chunk. For proposed 10.7s ref: ~160.
- **Seed is effectively fixed at -1.** Wrapper passes `seed=-1` when caller
  omits it; `api.infer` only replaces `None` with a random seed, not `-1`, so
  every call uses a deterministic seed. Run-to-run variance for identical text
  should be zero — confirms the "inconsistency" is about settings/ref mismatch,
  not stochasticity.
- **Model:** F5TTS_v1_Base (`model_1250000.safetensors`) confirmed from server log.
- **Precision.** Uses F5-TTS default (fp16 on CUDA/ROCm). No evidence of the
  bf16/fp16 issue from GitHub #1196.

## Change #4 — Strip markdown asterisks in `preprocessForTTS`

**Date:** 2026-04-20

**Why:** Found in F5 server log that Gemini is emitting markdown emphasis like
`*settles*`, `*vamps*`, `*swings*` in gen_text. F5's character-level tokenizer
reads asterisks as characters or as prosody hints that distort the alignment
model — which is exactly what "way too exaggerated delivery" feels like to a
listener.

**Change:** `server/src/services/broadcast/SegmentGenerator.ts` —
`preprocessForTTS` now:
- Strips `*word*` / `**word**` markdown emphasis wrappers
- Drops stray mismatched asterisks
- Normalizes curly double quotes `"..."` → `"..."` (F5's tokenizer handles
  straight quotes cleanly; curlies were mixed in gen_text like `"Found."`)

Four new tests in `SegmentGenerator.test.ts`; all 31 preprocessForTTS tests pass.

**Expected impact:** Large. Every script with emphasis markers was being read
with distorted prosody on the emphasized word. Asterisks appeared in 3/5
cold_opens in the last bake log.

**Outcome:** _pending deploy to prod + listen test_

## Change #5 — Patch F5 wrapper to actually trim leading silence

**Date:** 2026-04-20

**Why:** Probed F5 with a cold_open-sized text at current prod settings and
measured **528 ms of leading silence** in the generated audio. Dug into
`f5_tts/api.py` and found that `remove_silence=True` is a no-op unless the
caller also passes `file_wave=<path>` — our FastAPI wrapper bypasses
`export_wav` entirely (writes `wav` via `sf.write` directly to a buffer).
So `remove_silence=True` has been ignored for every call we've ever made.

**Change (on F5 server):** `~/f5tts-server/server.py` — added `_trim_silence()`
helper that trims leading/trailing silence on the numpy array before encoding
to WAV. Keeps 60 ms leading onset and 120 ms tail; threshold -40 dBFS.
Backup: `server.py.bak-20260420`. Service restarted via `systemctl restart f5tts`.

Before/after probe (same script, same settings):

| Config | Text | Duration | Lead | Tail | Wall |
|---|---|---|---|---|---|
| pre-patch (NFE=12) | cold_open | 14.14s | **528 ms** | 23 ms | 10.3s |
| post-patch (NFE=12, old cfg) | cold_open | 10.48s | **60 ms** | 55 ms | 11.3s |
| post-patch (NFE=20, new cfg) | cold_open | 10.47s | **60 ms** | 46 ms | 12.0s |
| post-patch (NFE=20, new cfg) | tight_bridge | 2.87s | 66 ms | 19 ms | 5.8s |

Leading silence now a consistent ~60 ms across every text length. NFE 12→20
adds ~0.7s wallclock on cold_open-length text.

**Expected impact:** Large on "dead air before voice speaks" complaint.
Independent of "first song hasn't played" — that's a client-side handoff
question to investigate separately.

**Outcome:** _live on F5 server; applies to every bake, prod or dev_

## Change #8 — Full recipe lock-in after A/B probes (2026-04-20)

**Why:** Bake review revealed three persistent issues: ONAY pronounced too
excitedly, artist names mispronounced, 50% robotic. Traced the common cause
to hyphens in phonetic substitutions — F5's character-level tokenizer reads
each hyphen-delimited syllable with its own emphatic stress.

**A/B methodology:** Generated 11 probe clips in three rounds, varying
hyphen treatment, reference audio, CFG, speed, and artist-name strategy.
User ranked; winning recipe was **Z2** = concatenated phonetics + cropped
reference (no "Oh-nay" in ref) + CFG 2.3 + speed 1.05 + NFE 20.

**Server-side changes (live on F5 server):**
- `~/f5tts-server/refs/onay-cartesia.wav`: cropped from 10.76s → 9.56s.
  Removed "You're listening to Oh-nay," section (splice at 1.67s → 2.87s
  silence boundaries, clean cut).
  Backup: `onay-cartesia.wav.bak2-20260420`.
- `~/f5tts-server/refs/onay-cartesia.txt`: new transcript without host-name
  mention. Backup: `onay-cartesia.txt.bak2-20260420`.

**Source changes (deployed to prod VPS):**
- `pronunciations.json` — 84/84 hyphens stripped from substitution values.
  Examples: `Bee-yon-say → Beeyonsay`, `Boss Man D-Low → Boss Man DLow`,
  `D-J Kah-led → DJ Kahled`, `Twenty-one Savage → Twentyone Savage`.
- `preprocessForTTS` — `ONAY → Oh-nay` changed to `ONAY → Ohnay`.
- `SegmentScriptBuilder` system prompt — pronunciation hint changed from
  `"Oh-nay"` → `"Ohnay"` so Gemini doesn't write hyphenated forms in
  generated scripts.
- Tests updated: 261/261 server tests pass.

**Prod `.env`:**
- `F5TTS_CFG_STRENGTH: 2.0 → 2.3` (stability bump, reduces excitement variance)
- `F5TTS_SPEED: 0.9 → 1.05` (base-pace-faster to compensate for
  phonetic-substitution drag)

**Cache:** TTS cache cleared again (8.8 MB accumulated since last wipe).
`pm2 reload cleo-broadcast` picked up new env. Health confirmed.

**Backups (prod):** `.env.bak2-20260420`, `SegmentGenerator.ts.bak2-20260420`,
`SegmentScriptBuilder.ts.bak-20260420`, `pronunciations.json.bak-20260420`.

**Rollback:** `cd ~/cleo-broadcast && cp *.bak2-20260420 ... && npm run build && pm2 reload cleo-broadcast` on prod; `cp .bak2-20260420 ...` on F5 server.

## Experiment: Fun-CosyVoice3-0.5B (rejected 2026-04-20)

Set up Alibaba's Fun-CosyVoice3-0.5B (Dec 2025, 0.5B params, Apache-2.0) on
the Linux box to A/B against F5's locked Z2 recipe. Install was bumpy on

## Change #10 — VoxCPM2 install + F5/CosyVoice retirement (2026-04-27)

GPU swapped from AMD 6700XT to NVIDIA RTX 5060 Ti 16 GB (Blackwell, sm_120).
F5-TTS and CosyVoice3 silently fell back to CPU since their installs were on
ROCm wheels — both `/health` reported `"device":"cpu"`. Used the swap as a
forcing function to evaluate VoxCPM2 (OpenBMB, 2B params, 48 kHz native, 30
languages, voice design + isolated cloning + ultimate cloning modes).

### Install

- **Path:** `~/voxcpm-server/`, Python 3.12 venv, FastAPI wrapper on
  `127.0.0.1:8002`. Wrapper schema mirrors F5 wrapper: `/tts`, `/tts.wav`,
  `/health`, `/voices`, `/clone`. Single `asyncio.Lock`-serialized inference
  (model holds prompt-cache state on `tts_model`).
- **PyTorch:** `torch 2.11.0+cu128` from `https://download.pytorch.org/whl/cu128`
  — required for Blackwell sm_120 support. Earlier wheels would silently CPU-fall.
- **Model:** `openbmb/VoxCPM2` weights cached to
  `~/.cache/huggingface/hub/models--openbmb--VoxCPM2/`. `bfloat16` on cuda.
- **Denoiser:** ZipEnhancer (`iic/speech_zipenhancer_ans_multiloss_16k_base`)
  loaded at startup with `VOXCPM_LOAD_DENOISER=1`. Cached to
  `~/.cache/modelscope/hub/models/iic/speech_zipenhancer_ans_multiloss_16k_base/`.
- **systemd:** `/etc/systemd/system/voxcpm.service`, restart-on-failure,
  journal logging, auto-start on boot. Boot env sets `VOXCPM_OPTIMIZE=0` and
  `VOXCPM_LOAD_DENOISER=1`.
- **Pangolin tunnel:** new rule `voxcpm.worthymedia.online` → port 8002.
  F5 tunnel `<TTS_TUNNEL>` decommissioned (was previously also
  hosting the `/cosy/*` proxy).

### A/B journey to validated recipe

User feedback drove the recipe iteration:

1. **Default settings (24 kHz reference clone):** "muddy, sibilant" — the
   `onay-cartesia.wav` reference is itself Cartesia-TTS-generated, so VoxCPM
   was faithfully cloning Cartesia's codec brightness in the 6–10 kHz band.
   F5/Cosy had been masking these artifacts via less-faithful synthesis;
   VoxCPM is a more transparent clone.
2. **48 kHz reference resample:** marginal — model upsamples internally, the
   artifacts were spectral, not rate-limited.
3. **`denoise: true` per-call (ZipEnhancer on the reference):** "perfect" audio
   quality. Adds ~3s per call on a 9.5s reference.
4. **Pacing regression after denoise:** "she sounds hurried again" — denoiser
   stripped subtle prosody cues from the reference. Restored deliberate pacing
   via inline style prefix `(slow, measured pace, late-night radio)` (VoxCPM's
   intended steering mechanism). Stack-friendly with C-style punctuation
   pauses already authored into Gemini prompts (em-dashes, ellipses, commas).
5. **Pre-denoised reference:** ZipEnhancer'd the reference once at install
   time, saved as `onay-cartesia-clean.wav`. Equivalent audio quality to
   `denoise: true` with no per-call cost. Output is 16 kHz (ZipEnhancer's
   native rate); model upsamples internally during clone.

**Final recipe** (lives in `VoxCpmProvider`):

| Parameter | Value |
|---|---|
| `ref_id` | `onay-cartesia-clean` (pre-denoised, 16 kHz) |
| `denoise` | `false` (ref is pre-cleaned) |
| Style prefix | `(slow, measured pace, late-night radio)` (provider-side injected) |
| `inference_timesteps` | `10` (range 4-30; per-tier tuning out of scope) |
| `cfg_value` | `2.0` |
| `use_prompt_mode` | `true` (ultimate-cloning, ref + prompt continuation) |

### Latency (5060 Ti, validated recipe)

| Tier | F5 prod (6700XT) | CosyVoice prod (6700XT) | VoxCPM2 (5060 Ti) |
|---|---|---|---|
| cold_open (~40w) | 10.5s | 14–16s | 13.3s |
| tight_bridge (~28w) | 2.9s | (~RTF 2 ≈ 8–10s) | 10.4s (ts=6) / 11.8s (ts=10) |
| deep_dive (~95w) | (n/a) | (~RTF 2 ≈ 50s) | 24.2s (ts=12) |

VoxCPM is comparable to or slightly faster than CosyVoice on cold_open, ~25%
slower than F5 on cold_open, and 3–4× slower than F5 on tight_bridges
(F5's 2.9s bridges were the outlier; CosyVoice was never that fast). For a
9-track standard broadcast (~6 segment calls), total TTS time ~70s vs F5's
~30s. User-facing time-to-first-audio is unchanged either way — slot 0 +
enrichment gates the response, not the full sequence.

### Failed experiments

- **`optimize=True` (torch.compile):** auto-warmup completes 10/10 steps but
  real `model.generate()` calls fail with bare `AssertionError()`. Likely a
  Blackwell sm_120 + bf16 + variable-shape autoregressive interaction in
  torch 2.11.0+cu128 (very fresh stack — 5060 Ti was released Q1 2026, torch
  2.11 in Mar 2026). Wrapper boots with `VOXCPM_OPTIMIZE=0`. Estimated
  30–50% latency win when fixed; revisit when torch ships better Blackwell
  support.
- **Voice design mode (no reference):** generated 3 ONAY-style voice
  descriptions (smoky-contralto / soft-intimate / editorial-measured). User
  preferred the cloned voice — voice design is a useful escape hatch for
  reference quality, but consistency across calls and voice character match
  for ONAY's specific identity weren't validated. Kept available via the
  wrapper (no `ref_id` triggers voice-design mode); not used in production.

### Code changes

- New `server/src/providers/tts/voxcpm.ts` (180 lines) — mirrors
  `cosyvoice.ts` schema, injects style prefix, defaults to pre-cleaned ref.
- Deleted `server/src/providers/tts/{f5tts,cosyvoice}.ts`.
- `server/src/providers/tts/index.ts`: removed F5/Cosy from
  `PROVIDER_CONSTRUCTORS`, registered `voxcpm`. Default fallback chain now
